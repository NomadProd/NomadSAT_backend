Practice Test Engine

Every rule the practice-test system enforces, as buttons you can press. The question this answers: does the state model hold up when someone pushes on it? A test runs the official four modules — Reading & Writing 1–2 then Math 1–2, 98 questions — and a half-built one must refuse to publish, a student must get exactly one attempt, a finished module must not reopen, and a grid-in answer must be graded the way College Board actually grades it. Each click returns the same status code the real API returns.

    Grid-in answer checker

    Math questions where the student types a value instead of picking a letter. The correct answer stored on this question is 2/3. Type what a student would type.

    —
    • Fractions need not be reduced — 2/4 is correct for 1/2.
    • A repeating decimal must fill the field, truncated or rounded at the last character: .6666, .6667, 0.666 and 0.667 pass; .666 and 0.66 do not.
    • Five characters, or six with a leading minus sign. No %, $, commas, or mixed numbers.

    Throwaway prototype — the page is disposable, the module behind it is not. The rules it runs are ports of services/practice_test_scoring.py and routes/practice_tests.py; the status codes and refusal messages are the ones those endpoints return. Nothing here talks to a server or a database, and no state survives a reload.
